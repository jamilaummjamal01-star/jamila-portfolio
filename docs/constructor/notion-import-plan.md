# План переноса базы из Notion

## Цель

Перенести текущие материалы в D1 без потери источника, но не копировать структуру длинных страниц один к одному.

## Источники

Первая партия импорта включает:

- центральный навигатор;
- 22 нишевые стратегии;
- конструктор диагностики;
- диагностические сессии и шаблон;
- библиотеку сценариев;
- нишевые вставки;
- модули и пакеты КП;
- тарифы;
- калькулятор стоимости.

Клиентские записи и реальные сессии переносятся отдельной партией после проверки приватности.

## Единица импорта

Одна строка импорта = одна атомарная запись.

Недопустимая строка:

> «Полная стратегия для косметики» со всем содержимым страницы.

Допустимые строки:

- один вопрос клиенту;
- один вероятный вопрос клиента;
- один ответ на возражение;
- одна проверка аудита;
- одно этическое правило;
- один пакет;
- один блок КП.

## Процесс импорта

### Шаг 1. Выгрузка

Каждая исходная страница сохраняется с:

- Notion page ID;
- URL;
- заголовком;
- датой изменения;
- полным исходным текстом.

### Шаг 2. Разметка блоков

Содержимое делится по заголовкам и смысловым единицам.

Каждый блок получает предварительный тип:

- вопрос;
- ответ;
- сценарий;
- правило;
- риск;
- пакет;
- тариф;
- описание.

### Шаг 3. Атомаризация

Один блок делится, если внутри содержится несколько самостоятельных действий.

Пример:

> «Уточните сроки, бюджет и кто согласует проект»

превращается в три отдельных вопроса.

### Шаг 4. Нормализация

Выполняется:

- удаление лишних пробелов;
- единое написание AI;
- единые названия ниш и этапов;
- сохранение обращения «Вы»;
- сохранение тёплого делового тона;
- удаление внутренних служебных фраз из клиентских текстов;
- отказ от формулировки «Если хотите»;
- проверка, что ответ не заканчивается обещанием гарантированного результата.

### Шаг 5. Поиск дублей

Сравниваются:

- нормализованный текст;
- тип;
- категория;
- ниша;
- этап;
- смысл следующего действия.

Результат:

- точный дубль — пропустить;
- вариант формулировки — добавить в существующую запись;
- близкий, но другой контекст — сохранить как отдельную запись со связью.

### Шаг 6. Предпросмотр

До записи в D1 интерфейс показывает:

- новые записи;
- возможные дубли;
- ошибки классификации;
- отсутствующие ниши;
- вопросы клиента без ответа;
- высокорисковые записи;
- записи с длинным неразделённым текстом.

### Шаг 7. Подтверждение

Импорт выполняется только после ручного подтверждения партии.

Все новые записи из Notion получают статус `review`, а не `approved`.

### Шаг 8. Проверка

Запись становится `approved`, когда проверены:

- тип;
- контекст;
- клиентский текст;
- следующий шаг;
- риск;
- источник;
- нишевые связи.

## Очерёдность переноса

### Партия 1. Универсальное ядро

- общая диагностика;
- стоимость;
- сроки;
- правки;
- AI;
- права;
- исходники;
- конфиденциальность;
- гарантии;
- общие сценарии.

### Партия 2. Пилотные ниши

1. бренды одежды и текстиля;
2. косметика и уход;
3. маркетплейсы.

### Партия 3. Приоритет A

- исламские товары;
- производители;
- эксперты;
- образование;
- B2B;
- украшения;
- товары для дома.

### Партия 4. Остальные ниши

Переносятся после теста интерфейса и корректировки классификации.

### Партия 5. Тарифы, пакеты и КП

Переносятся после утверждения внутренней модели стоимости.

## Приватность

Перед импортом реальных клиентов удаляются или отдельно защищаются:

- личные телефоны;
- email;
- закрытые переписки;
- медицинские данные;
- данные детей;
- документы;
- адреса;
- неопубликованные финансовые условия.

Для первой версии импортируется база знаний без персональных данных клиентов.

## Резервное копирование

Перед каждой крупной партией:

1. экспорт текущей D1-базы;
2. создание `import_batches`;
3. предпросмотр;
4. импорт;
5. отчёт об ошибках;
6. возможность откатить записи по `import_batch_id` в следующей миграции.

## Критерий успешного переноса

Материал считается перенесённым не тогда, когда текст появился в D1, а когда его можно найти по реальному рабочему запросу:

- «Что спросить бренд косметики перед рекламным роликом?»;
- «Что ответить на вопрос о гарантии продаж?»;
- «Какие риски проверить у детского проекта?»;
- «Какие блоки включить в КП B2B-поставщику?».
